# 书店 · 图书台账与进销存

基于 Spring Boot + Vue 3（Element Plus）的全栈小应用：维护图书台账，并以进货单入库加库存、销售单结账扣库存（不足拦截、退款回滚）的进销存数量联动。

## 启停

```bash
sh start.sh   # 启动（docker compose 拉起 mysql / backend / frontend）
sh stop.sh    # 停止
```

后端接口以 `/api` 为前缀（`/api/books`、`/api/suppliers`、`/api/purchases`、`/api/sales`），前端使用 hash 路由。

## ISBN 查询与图书详情

- 图书列表支持按**完整或部分 ISBN** 查询（独立输入框，后端 `isbn` 参数做包含匹配），结果展示书名、作者、定价、库存与销售状态；每行「详情」按**图书主键**打开 `/books/:id` 详情页，销售单明细的「查看图书」同样按主键跳转——与列表排序、分页无关，不会跳错书。
- 查询条件与分页写入地址栏（`#/books?isbn=…&page=…`），刷新或从详情「返回列表」后结果保持一致；列表（不分页）、分页与详情接口共用同一套过滤规则（`BookSpecifications`）。
- 空值不当任意匹配：ISBN 只输入空白时页面明确提示、不发查询；`isbn` 为 NULL 的旧数据不参与 ISBN 匹配。空结果、ISBN 缺失（「未登记」）、重复 ISBN 档案在页面上都有明确提示。
- 高频连续查询只采纳最后一次请求的结果，较慢的前一次响应不会覆盖新结果（图书列表、销售单明细切换同理）。
- 旧数据兼容：`book.isbn` 可空，启动时幂等迁移（补列 / 放宽 NOT NULL / 无重复值时补唯一索引）；销售单详情内嵌图书快照，图书档案缺失的旧明细显示为空而不报错。
- 接口：`GET /api/books?status=&keyword=&isbn=&page=&size=`（不带分页参数时返回完整列表）、`GET /api/books/{id}`。

## 供应商启用 / 停用

- 供应商带可追踪状态：`启用 / 停用`、停用原因、最近变更时间；每次停用/启用都写入 `supplier_status_log` 流水（供应商页「变更记录」可查）。已有供应商默认保持启用。
- 新建采购草稿只能选择启用供应商；供应商停用后，其名下**已有草稿保留原供应商关系**，仍可查看、补充明细，但**不能入库**，也不能把草稿改挂给停用供应商。
- 入库前在同一事务内用行锁重新校验供应商状态：已停用则**整单拒绝**，采购单状态、图书库存、明细全部回滚、无半更新；重新启用后原草稿可继续入库。
- 停用/启用、建草稿、入库并发时由数据库行锁串行（`SELECT … FOR UPDATE`），不会出现「显示已停用却建成新单」「重复入库」「只更新一半」；并发冲突返回 409，前端提示刷新后安全重试。
- 旧库兼容：应用启动时幂等迁移（补状态列、回填启用、建流水表），旧供应商与旧草稿无需手工处理。
- 状态接口：`GET /api/suppliers?status=启用|停用`、`POST /api/suppliers/{id}/status`（body：`{status, reason}`，停用必填原因）、`GET /api/suppliers/{id}/status-logs`。

## 销售单结账 / 退款（库存联动与并发）

- **退款一次性、可追溯**：已结账销售单退款在**同一个数据库事务**内完成「逐本恢复库存 + 销售单置已退款 + 写退款时间 `refunded_at` + 追加退款库存流水」，要么整单成功要么整单回滚，不会出现「页面显示已退款但库存没恢复」的半更新。列表与详情都展示退款时间。
- **结账快照**：结账时把每本书的书名 / ISBN / 单价固化到销售明细。之后图书改名、改价甚至档案被删除，销售单详情仍按快照展示原凭证；明细图书档案缺失的旧单不报错，详情明确标注「档案缺失」并保留快照。
- **档案缺失整单拒绝**：退款前先整单校验，只要有一本明细的图书档案缺失（无法核对回滚），就**一本都不动**、状态不改，整单拒绝并列出缺失书名（取快照），提示补建档案后刷新重试，绝不只回滚部分明细。
- **并发只生效一次**：结账 / 退款先 `SELECT … FOR UPDATE` 锁销售单头并在锁内复查状态，再**统一按图书 id 升序**锁全部图书（与新销售单结账、进货入库 / 作废同一加锁顺序，避免死锁）。重复点击、刷新重试、两名操作员同时退款时，只有一个请求能在「已结账」下继续；后到者在锁内读到「已退款」直接拒绝。库存流水表 `(biz_type,biz_id,book_id)` 唯一约束是数据库层的第二道防线，任何情况下一条退款最多产生一次回滚、一条流水。
- **与新销售单占用一致**：退款与新销售单结账在同一把图书行锁上串行，库存校验与状态变更读得到的永远是一致值；抢锁超时返回 409，单据未做任何变更，提示刷新后安全重试。数据库另有 `book.stock >= 0` 的 CHECK 约束兜底，任何路径都不能写出负库存。
- **页面跟随后端最新状态**：结账 / 退款按钮依据最新单据状态与明细完整性禁用（已退款不可重复退、档案缺失单不可退），请求进行中按钮 loading 防连点；操作返回后（无论成功失败 / 并发冲突）强制重新拉取列表与详情，过期页面会被后端真实状态覆盖。
- **库存流水可核对**：每笔销售结账扣减、退款回滚、进货入库、入库单作废都在业务事务内追加一条 `stock_ledger`（含增量与变更后余量），图书详情页可逐笔查看，财务库存与销售 / 进货记录对得上。接口：`GET /api/books/{id}/stock-ledgers`。
- 旧库兼容：应用启动时幂等迁移（补 `sale.refunded_at`、补明细快照列并按当前档案回填、建 `stock_ledger` 表与非负库存约束）；迁移前的历史单据不补造流水，迁移后所有库存变动逐笔留痕。
